# HTTPS для Снабдрайв: от сертификата до включения

Приложение к переходу на https готово: перенаправление http→https, HSTS, политика `Secure`
для cookie и `upgrade-insecure-requests` реализованы и выключены одной секцией `Security`.
Внешних ресурсов в разметке нет (ни CDN, ни сторонних скриптов — только свои `css/app.css`,
`js/panel.js` и `_framework/blazor.web.js`), поэтому «смешанного содержимого» после перехода
не возникнет. Blazor-циркул сам перейдёт на `wss://`, ничего настраивать не нужно.

Осталось получить сертификат и включить три настройки. Порядок действий ниже.

---

## Шаг 0. Откуда брать сертификат

| Путь | Когда подходит | Цена | Что увидят пользователи | Продление |
|------|----------------|------|--------------------------|-----------|
| **A. Let's Encrypt** | есть публичный домен; сайт виден из интернета **или** вы можете создавать DNS-записи | бесплатно | замок без предупреждений | автоматически, каждые ~60 дней |
| **B. Свой УЦ (AD CS)** | есть домен Active Directory | бесплатно | замок без предупреждений на всех доменных ПК | вручную, раз в 1–2 года |
| **C. Самоподписанный** | ни домена, ни AD; чистая внутренняя сеть | бесплатно | предупреждение, пока сертификат не разложен по ПК | вручную, раз в N лет |

Для внутренней сети лучший вариант — **B**: сертификат от вашего УЦ доменные компьютеры
начинают доверять автоматически через групповые политики, пользователям не нужно ничего
устанавливать. Если AD нет — берите **C** и разложите сертификат по машинам один раз.

---

## Путь A. Let's Encrypt через win-acme

1. **DNS.** Создайте A-запись, например `snab.ваш-домен.ru`, указывающую на внешний IP сервера.
   Пользователи внутри сети могут резолвить это имя во внутренний адрес через внутренний DNS
   или файл hosts — сертификат от этого не зависит, важно лишь совпадение имени.
2. **Скачайте** [win-acme](https://www.win-acme.com/) и распакуйте, например, в `C:\Tools\win-acme`.
3. **Запустите** `wacs.exe`:
   - `M` — create certificate;
   - выберите способ привязки — `1` (IIS) и ваш сайт;
   - тип валидации:
     - сайт доступен из интернета по порту 80 → `http-01` (win-acme сам положит проверочный
       файл в `.well-known`);
     - сайт только внутренний → `dns-01` (нужен API вашего регистратора — win-acme умеет
       работать с Cloudflare, Route53, Azure DNS и другими; TXT-запись создаётся сама).
4. **Хранилище.** Выберите Certificate Store → `LocalMachine\My`; win-acme сам создаст
   https-привязку в IIS.
5. **Продление.** win-acme создаёт задачу Планировщика `win-acme renew` и обновляет
   сертификат примерно каждые 60 дней без вашего участия. Проверить можно так:
   `wacs.exe` → `L` (list) — покажет дату следующего обновления; или в Планировщике заданий.

Что должно быть открыто: порт 80 из интернета для `http-01` (и порт 443 для самого сайта).
Если сайт наружу не выпускают — только `dns-01`.

## Путь B. Свой центр сертификации (Active Directory)

1. Убедитесь, что в домене установлена роль **Active Directory Certificate Services**
   (обычно на контроллере домена). Проверка: `certsrv` открывается, или в «Службах» есть
   `Active Directory Certificate Services`.
2. На сервере Снабдрайв откройте `certlm.msc` → **Личное** → правый клик →
   **Все задачи → Запросить новый сертификат**.
3. Выберите шаблон **Веб-сервер** (Web Server), нажмите «Дополнительные сведения» и в поле
   **Альтернативное имя субъекта (SAN)** впишите **все** имена, по которым пользователи
   открывают сайт:
   - `snab`
   - `snab.company.local` (ваше полное имя)
   - IP-адрес `192.168.23.50` (тип «IP-адрес»)
4. Завершите запрос — сертификат появится в «Личное». Доменные компьютеры доверяют вашему
   корневому УЦ автоматически, поэтому пользователям ничего устанавливать не нужно.
5. Срок действия задаётся шаблоном (обычно 2 года). Поставьте напоминание о продлении —
   истёкший сертификат при включённом HSTS заблокирует вход полностью (см. шаг 4).

## Путь C. Самоподписанный сертификат

На сервере, в PowerShell **от имени администратора**:

```powershell
$cert = New-SelfSignedCertificate `
    -CertStoreLocation "Cert:\LocalMachine\My" `
    -DnsName "snab","snab.company.local" `
    -TextExtension @(
        "2.5.29.37={text}1.3.6.1.5.5.7.3.1",
        "2.5.29.17={text}DNS=snab&DNS=snab.company.local&IP=192.168.23.50") `
    -KeyUsage DigitalSignature,KeyEncipherment `
    -KeyAlgorithm RSA -KeyLength 2048 `
    -NotAfter (Get-Date).AddYears(5) `
    -FriendlyName "SnabDrive Web"

$cert.Thumbprint          # запишите отпечаток — он нужен для привязки
```

Важно: в SAN (`2.5.29.17`) должны быть и DNS-имена, и IP. Браузер сверяет адресную строку
с SAN, а не с «выдано для», поэтому если пользователи ходят по `https://192.168.23.50`,
IP обязан быть в списке.

Экспорт **без** закрытого ключа (этот файл пойдёт на рабочие станции):

```powershell
Export-Certificate -Cert "Cert:\LocalMachine\My\<ОТПЕЧАТОК>" -FilePath C:\Temp\snabdrive.cer
```

Раскладка на компьютеры пользователей:

- **Через GPO (правильно):** редактор групповых политик домена → Конфигурация компьютера →
  Политики → Конфигурация Windows → Параметры безопасности → Политики открытых ключей →
  **Доверенные корневые центры сертификации** → добавить `snabdrive.cer`. После обновления
  политик (`gpupdate /force`) предупреждения исчезнут у всех.
- **Вручную (для пары машин):** двойной клик по `.cer` → «Установка сертификата» →
  «Локальному компьютеру» → «Поместить все сертификаты в следующее хранилище» →
  «Доверенные корневые центры сертификации».

## Шаг 1. Привязка сертификата в IIS

**Через интерфейс** (проще всего):

1. Диспетчер IIS → узел сервера → **Сертфикаты сервера** — убедитесь, что сертификат там есть.
2. Сайты → ваш сайт → **Привязки…** → **Добавить**.
3. Тип: `https`, порт: `443`, IP: «Все не назначенные», сертификат: выбрать из списка.
4. Привязку `http` на порту 80 **оставьте** — по ней приложение будет редиректить на https.
   Если хотите заставить всех ходить только по https и не редиректить — удалите её.

**Через PowerShell** (вариант, если сайта ещё нет в списке привязок):

```powershell
New-WebBinding -Name "SnabDrive" -Protocol https -Port 443
$thumb = "<ОТПЕЧАТОК>"
New-Item -Path "IIS:\SslBindings\0.0.0.0!443" -Value (Get-Item "Cert:\LocalMachine\My\$thumb")
```

Проверка: `https://snab.company.local` открывается, в адресной строке замок без предупреждений.

## Шаг 2. Включить https в приложении

В `C:\inetpub\snabdrive\appsettings.Production.json` добавьте (или поправьте) секцию:

```json
"Security": {
  "EnableHttpsRedirection": true,
  "HttpsPort": 443,
  "CookieSecurePolicy": "Always",
  "UpgradeInsecureRequests": true,
  "EnableHsts": true,
  "HstsMaxAgeDays": 30
}
```

Что делает каждая настройка:

| Настройка | Эффект |
|-----------|--------|
| `EnableHttpsRedirection` | `http://…` отвечает 307 и отправляет на `https://…` |
| `HttpsPort` | порт в адресе редиректа (под IIS in-process приложение не всегда определяет его само; продублировано в `web.config` переменной `ASPNETCORE_HTTPS_PORT`) |
| `CookieSecurePolicy: "Always"` | cookie входа `SnabDrive.Auth` больше не передаётся по http — украсть её прослушиванием сети нельзя |
| `UpgradeInsecureRequests` | браузер сам поднимает любые http-запросы страницы до https |
| `EnableHsts` + `HstsMaxAgeDays` | браузер запоминает «только https» на указанный срок |

Затем перезапустите пул приложений.

---

## Шаг 3. Проверить (10 минут)

1. `https://адрес` открывается с замком, предупреждений нет.
2. `http://адрес` → перенаправление на `https://` (в DevTools видно `307 Temporary Redirect`).
3. F12 → Network → первый документ: есть заголовки `Strict-Transport-Security`,
   `Content-Security-Policy`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`.
4. F12 → Application → Cookies: у `SnabDrive.Auth` стоят флаги `Secure`, `HttpOnly`,
   `SameSite=Lax`.
5. F12 → Console: нет сообщений о смешанном содержимом («Mixed Content») и нет
   «Refused to …» от CSP.
6. F12 → Network → WS: соединение `_blazor` идёт по `wss://`, статус 101, страница реагирует
   на изменения (realtime работает).
7. Войти и выйти, приложить файл, открыть вложение — всё работает по https.

## Шаг 4. HSTS — включайте осознанно

Получив заголовок `Strict-Transport-Security`, браузер запоминает требование на весь
`HstsMaxAgeDays` и **больше не пускает сайт по http**, показывая ошибку без кнопки
«всё равно перейти». Поэтому:

- начинайте с `HstsMaxAgeDays: 30` — за месяц станет ясно, что сертификат и привязка
  работают устойчиво; потом поднимайте до `365`;
- следите за сроком сертификата. Истёкший сертификат при включённом HSTS = полный отказ
  доступа для всех, кто уже заходил;
- если нужно срочно откатиться на http: поставьте `EnableHsts: false`, но у уже заходивших
  пользователей ограничение останется до конца срока — лечится только очисткой
  `chrome://net-internals/#hsts` (или `edge://`), либо ожиданием;
- совсем убрать HSTS из разработки нельзя и не нужно: заголовок выдаётся только вне
  режима Development и браузерами игнорируется в ответах по http.

## Типовые проблемы

| Симптом | Причина и решение |
|---------|-------------------|
| В журнале «Failed to determine the https port for redirect», редиректа нет | Не задан порт. У нас он берётся из `Security:HttpsPort` и продублирован в `web.config` (`ASPNETCORE_HTTPS_PORT=443`); проверьте, что оба равны порту привязки |
| Редирект зацикливается (ERR_TOO_MANY_REDIRECTS) | В `web.config` стоит `hostingModel="outofprocess"`: IIS терминирует https, а приложение видит http. Верните `inprocess` (как в нашем `web.config`) либо настройте ForwardedHeaders |
| У пользователей предупреждение о сертификате | Имя в адресной строке не совпадает ни с одним SAN сертификата. Перевыпустите сертификат, добавив это имя/IP |
| «Ваше подключение не защищено» только у части сотрудников | Самоподписанный сертификат не разложен на эти машины (путь C) |
| Вход не работает сразу после включения `CookieSecurePolicy: "Always"` | Кто-то заходит по `http://` в обход редиректа (закладка на http при удалённой 80-й привязке). Либо верните привязку http для редиректа, либо обновите закладки |
| Blazor не подключается по https | Прокси/фаервол режет WebSocket. Нужен проход `wss://адрес/_blazor` |

## Дополнительно: версии TLS

Windows Server 2019/2022 поставляются с отключёнными TLS 1.0/1.1 — проверять ничего не нужно.
На Server 2016 старые протоколы можно выключить в реестре
(`HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Protocols`) — после этого
обязателен перезапуск сервера. Современные браузеры работают по TLS 1.2 и 1.3.
