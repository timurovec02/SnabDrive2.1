# Настройка Битрикс24 для «Снабдрайв»

Все уведомления и обращения в техподдержку уходят в Битрикс24: личные уведомления сотрудникам
(переносы задач, торги) и заявки с кнопки «Техподдержка» (в общий чат или уведомлением).

## 1. Портал и входящий вебхук

1. Откройте (или зарегистрируйте) портал Битрикс24 — например `https://вашафирма.bitrix24.ru`.
   Бесплатного тарифа достаточно.
2. В портале откройте **Разработчикам → Другие методы → Входящие вебхуки**
   (прямая ссылка: `https://вашафирма.bitrix24.ru/devops/`). Создайте вебхук:
   - **Ответственный пользователь** — сотрудник, от чьего имени отправляются сообщения
     (обычно администратор). Уведомления без указанного получателя придут именно ему.
   - **Права (scopes)**: отметьте **«Диалоги и сообщения» (im)** — этого хватает для
     уведомлений и чата. Если сомневаетесь — «Полный доступ».
3. Скопируйте URL вида `https://вашафирма.bitrix24.ru/rest/1/КОД_ВЕБХУКА/` — это и есть адрес вебхука.

## 2. Конфигурация сайта

На сервере в `C:\inetpub\snabdrive\appsettings.Production.json` (этот файл не попадает в git):

```json
"Bitrix": {
  "WebhookUrl": "https://вашафирма.bitrix24.ru/rest/1/КОД_ВЕБХУКА/",
  "SupportChatId": "chat42",
  "SupportToUserId": ""
}
```

- `WebhookUrl` — обязательно; адрес из шага 1.
- `SupportChatId` — ID **общего чата** техподдержки (шаг 3). Пусто — обращения приходят
  уведомлением владельцу вебхука (или `SupportToUserId`).
- `SupportToUserId` — числовой ID сотрудника, кому слать обращения, если чат не задан.

Альтернатива файлу — переменные окружения: `Bitrix__WebhookUrl`, `Bitrix__SupportChatId`,
`Bitrix__SupportToUserId`. После изменения конфигурации перезапустите пул приложений
(`iisreset`) и обновите страницу с Ctrl+F5.

## 3. Чат техподдержки (общий чат)

1. В Битрикс24 создайте групповой чат «Техподдержка Снабдрайв» и добавьте сотрудников,
   которые отвечают на обращения (вебхук-пользователь тоже должен состоять в чате).
2. Узнайте ID чата: откройте чат в браузере — в адресе виден фрагмент вида `chat42`;
   либо методом REST `im.chat.list`. Если у вас есть только число — впишите его,
   сайт сам добавит `chat`.
3. Впишите ID в `Bitrix:SupportChatId`.

Обращения с кнопки «Техподдержка» появляются в этом чате: тема, автор, страница и текст.
Ответить пользователю можно лично из Битрикс24 — его контакт указан в сообщении.

## 4. Личные уведомления сотрудникам

Переносы задач и уведомления о торгах приходят сотрудникам лично. Для этого:

1. Узнайте числовой ID сотрудника в Битрикс24: адрес профиля вида
   `https://вашафирма.bitrix24.ru/company/personal/user/123/` → ID = `123`.
2. В «Снабдрайв» → **Пользователи** заполните поле **«ID сотрудника в Битрикс24»** и сохраните.
3. Нажмите кнопку **«Тест»** рядом с пользователем — придёт тестовое уведомление.
   Если не пришло, текст ошибки Битрикс24 показывается в подсказке.

## 5. Проверка канала техподдержки

Кнопка **«Техподдержка»** (в шапке сайта) → **«Проверить доставку»** — отправляет тестовое
сообщение тем же маршрутом, что и обращения (в чат или уведомлением). Увидели сообщение
в Битрикс24 — канал работает. Ошибка Битрикс24 показывается прямо в окне.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| «Вебхук Битрикс24 не настроен» | Не задан `Bitrix:WebhookUrl` в `appsettings.Production.json` (или переменной окружения). После правки — `iisreset`. |
| Битрикс24 вернул 401 / NOT_AUTHORIZED | Неверный URL вебхука (опечатка, лишние пробелы) или вебхук удалён. Создайте заново. |
| Битрикс24 вернул 403 / ACCESS_DENIED | У вебхука нет права «Диалоги и сообщения» (im). Отредактируйте вебхук и добавьте права. |
| Сообщение не появляется в чате | Неверный `SupportChatId`, либо вебхук-пользователь не состоит в чате. Временно очистите `SupportChatId` — обращения пойдут уведомлением владельцу вебхука. |
| Личное уведомление не пришло | Не заполнен или неверен «ID сотрудника в Битрикс24» у пользователя — проверьте кнопкой «Тест». |
| Сайт не поднялся после правки | Опечатка в JSON (запятая, кавычки). Проверьте синтаксис `appsettings.Production.json`. |
